# Learning objectives and evidence

An objective is demonstrated by an observable action. These are program outcomes; the repository does not claim that every outcome is already taught by a completed lesson.

| Stage | You should be able to | Evidence to produce |
|---|---|---|
| Orientation | Define dataset, feature, target, model, training, and inference in ordinary language | Annotated five-row dataset and hand-calculated baseline |
| Python | Write functions, inspect types and exceptions, load local data, and manipulate arrays | Reproducible notebook with shape and value checks |
| Mathematics | Explain symbols and units; derive weighted sums, losses, gradients, and basic probability | Worked calculations with numerical verification |
| Data | Diagnose missingness, duplicates, category issues, and leakage | Data-quality report and train-only preprocessing pipeline |
| Foundations | Distinguish training fit, validation selection, and test assessment | Written experimental protocol established before tuning |
| Regression | Derive and compare numerical prediction methods | Scratch and library agreement; residual analysis |
| Classification | Connect probabilities, thresholds, and error costs | Confusion matrix and threshold analysis with held-out data |
| Ensembles | Explain randomization, averaging, and sequential error correction | Controlled comparison of trees, bagging, and boosting |
| Evaluation | Choose folds that respect class, entity, and time dependence | Reproducible search with uncertainty and untouched test results |
| Unsupervised learning | Distinguish useful representations from arbitrary visual patterns | Stability analysis, reconstruction or neighborhood diagnostics |
| Anomalies | Evaluate rare-event alerts against operational costs | Precision/recall and review workload at chosen thresholds |
| Time series | Construct features available at forecast time | Rolling-origin evaluation against naive seasonal baselines |
| Probabilistic ML | Distinguish uncertainty sources and approximate inference | Prior/posterior explanation and calibration diagnostics |
| Neural/deep learning | Derive backpropagation and trace tensor shapes | NumPy network followed by a tested CPU PyTorch loop |
| Language/vision | Match representation and metric to task | Small local experiment with dataset and error limitations |
| Recommenders | Separate exposure, preference, and ranking quality | Temporal split and cold-start evaluation |
| Reinforcement learning | Explain state, policy, return, and value updates | Repeated seeded small-environment experiments |
| Advanced paradigms | Adapt protocols to label scarcity and changing distributions | Clear assumptions and comparison to a simpler baseline |
| Responsible ML | Audit subgroup errors, explanations, privacy, and robustness | Model card with unresolved risks and justified boundaries |
| Deployment | Validate, serve, test, version, and monitor a model | Local API, integration tests, artifact manifest, monitoring plan |
| Capstones | Connect business question to defensible evidence | End-to-end report that separates results from speculation |

Use the [assessment rubric](assessments/README.md) for mastery decisions and [PROGRESS.md](PROGRESS.md) for repository implementation status.

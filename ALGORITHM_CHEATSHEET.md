# Algorithm comparison — classical core edition

This substantive core guide supports planning and revision; it does not claim the corresponding algorithm notebooks are already implemented. The [inventory](reference_materials/notebook_inventory.json) preserves every requested specialized and advanced algorithm. Expanding this into the complete per-algorithm advanced guide remains tracked in [PROGRESS.md](PROGRESS.md).

“Small,” “medium,” and “large” depend on feature count, sparsity, memory, and implementation. Benchmark on a representative subset. Hyperparameters below name influential controls, not universally optimal defaults. Always fit preprocessing within training folds and compare against a baseline.

| Algorithm / learning task | Mechanism and assumptions | Advantages and when to use | Limitations and when to avoid | Scale considerations and important controls |
|---|---|---|---|---|
| Mean/median baseline; supervised regression | Predict a single training summary; future outcomes should resemble the training population | Essential reference, transparent and cheap | Ignores features, seasonality, and interactions | Linear pass through targets; `strategy`, validation of window length |
| Simple/multiple linear regression, OLS; supervised regression | Minimize squared residuals with an affine predictor; conditional mean is approximated linearly | Interpretable coefficients and strong numerical baseline | Sensitive to extreme residuals; correlated features destabilize coefficients; classical inference requires additional assumptions | Dense solvers depend strongly on feature count; `fit_intercept`, feature design; prefer stable least-squares solvers to explicit inverse |
| Polynomial regression; supervised regression | Expand features into powers/interactions, then fit a linear model in those features | Curved relationships with familiar linear machinery | Feature count can grow rapidly; extrapolation and overfitting can be severe | `degree`, interaction selection, regularization; scale within a pipeline |
| Ridge; supervised regression | Squared-error fit plus L2 coefficient penalty | Stabilizes correlated predictors; useful when many features have small effects | Usually retains all coefficients; scale-dependent penalty | `alpha`, solver, feature scaling; moderate to high-dimensional problems |
| Lasso; supervised regression | Squared-error fit plus L1 penalty | Produces sparse coefficient sets when sparsity is useful | Correlated variables can be selected unstably; not automatic scientific feature discovery | `alpha`, convergence tolerance, scaling; inspect convergence and stability |
| Elastic Net; supervised regression | Mix L1 and L2 penalties | Combines sparsity with more stable treatment of correlated features | Requires tuning two penalty controls; coefficients remain association-based | `alpha`, `l1_ratio`, iterations; useful with many correlated inputs |
| Huber; supervised regression | Quadratic loss near zero residual, approximately linear for large residuals | Reduces influence of some response outliers | Not immune to high-leverage input outliers or arbitrary contamination | `epsilon`, `alpha`, scaling; inspect the identified residual pattern |
| Quantile regression; supervised regression | Asymmetric absolute loss estimates a conditional quantile | Predicts upper/lower outcomes aligned with asymmetric costs | Multiple independently fitted quantiles can cross; extremes need sufficient data | `quantile`, penalty strength, solver; interpretation is a quantile rather than a mean |
| Poisson regression; supervised count prediction | Log link maps a linear predictor to positive mean counts | Useful for nonnegative event counts with appropriate exposure treatment | Conditional variance assumptions can be restrictive; excess zeros and overdispersion need investigation | `alpha`, exposure/offset formulation, iterations; do not treat exposure differences as ordinary noise |
| Logistic/softmax regression; supervised classification | Linear class scores transformed into probabilities and fitted by likelihood | Strong interpretable baseline for dense or sparse features | Linear boundaries in the chosen representation; regularization and calibration still matter | `C`, penalty, solver; large sparse text often practical |
| Perceptron/SGD classifier; supervised classification | Repeated updates from individual or small batches of examples | Efficient incremental learning and large sparse problems | Sensitive to scaling, order, objective, and learning schedule | `loss`, `alpha`, learning-rate schedule, epochs; linear boundary unless features change |
| KNN classifier/regressor; supervised prediction | Vote or average among nearby training examples | Simple nonlinear baseline with little fitting | Sensitive to distance, irrelevant features, and scale; costly prediction; weak extrapolation | `n_neighbors`, `weights`, metric; retains training data and degrades in high dimension |
| Gaussian Naive Bayes; supervised classification | Class-conditional normal feature models with conditional independence assumption | Very fast small-data baseline | Independence and Gaussian assumptions can fail; probability confidence may be poor | `var_smoothing`; scales roughly linearly with examples and features |
| Multinomial Naive Bayes; supervised classification | Class-specific probabilities for nonnegative count-like features | Fast text baseline with sparse counts | Not suited to arbitrary signed continuous features; independence is restrictive | `alpha` smoothing, priors; efficient for large sparse vocabularies |
| Bernoulli Naive Bayes; supervised classification | Model binary feature presence/absence within each class | Natural for binary event indicators | Discards counts unless binary behavior is intended | `alpha`, `binarize`; feature encoding defines the model's meaning |
| LDA; supervised classification | Gaussian classes share covariance, producing linear boundaries | Can work well with limited data when assumptions are reasonable | Shared covariance and Gaussian shape may be inadequate | Solver, shrinkage; high feature count requires covariance care |
| QDA; supervised classification | Gaussian classes have separate covariances | Allows curved boundaries without kernels | More covariance parameters require more data; singular estimates can fail | `reg_param`; avoid unregularized fits with too few examples per class |
| Linear SVM; supervised classification | Maximize margin with penalties for violations | Effective in high-dimensional sparse spaces | Scores are not automatically probabilities; scale matters | `C`, loss, class weighting; linear implementations scale better than general kernel SVM |
| Kernel SVM/SVR; supervised classification/regression | Similarity kernel creates nonlinear decision/prediction functions | Flexible medium-sized nonlinear problems | Training and prediction can become expensive; kernel and scale sensitivity | `C`, `kernel`, `gamma`, regression `epsilon`; many support vectors increase cost |
| Decision tree; supervised classification/regression | Greedy feature splits reduce impurity or target loss | Nonlinear interactions, mixed feature scales, inspectable small trees | High variance, unstable splits, limited extrapolation | `max_depth`, `min_samples_leaf`, pruning `ccp_alpha`; deep trees can memorize |
| Random forest; supervised prediction | Average randomized trees trained on resampled data | Strong tabular baseline, reduced variance, limited scaling needs | Larger artifacts; explanations can obscure dependence; no regression extrapolation beyond leaf averages | `n_estimators`, `max_features`, leaf size; training parallelizes but memory grows |
| Extra Trees; supervised prediction | More randomized split thresholds across many trees | Often fast and reduces variance through stronger randomization | Extra randomness may increase bias | Number of trees, feature subsampling, leaf size; compare empirically to forests |
| Bagging; supervised ensemble | Fit base estimators on resampled data and aggregate | Helps unstable learners such as trees | Less benefit for already stable biased estimators | Base learner, number of estimators, sample fraction; multiplies fitting cost |
| AdaBoost; supervised ensemble | Sequentially emphasize poorly handled observations | Combines weak learners into a stronger decision rule | Can be sensitive to mislabeled or extreme observations | Learning rate, number and complexity of base learners; validate noise sensitivity |
| Gradient/Histogram Gradient Boosting; supervised prediction | Sequentially fit corrections to a differentiable loss; histogram variant bins features | Strong nonlinear tabular performance | Tuning and stopping matter; sequential stages limit parallelism | Learning rate, iterations, leaves, regularization; histogram methods suit larger tables |
| Voting; supervised ensemble | Combine fitted model predictions by labels, probabilities, or averages | Simple diversity-based combination | Correlated errors limit gains; probability scales may differ | Weights, hard/soft voting; evaluate calibration for probability voting |
| Stacking; supervised ensemble | Learn a combiner using out-of-fold base predictions | Learns complementary behavior across model families | In-sample base predictions leak training fit into the combiner | Cross-validation design, final estimator; costs multiple fits per model |
| K-Means/K-Means++; unsupervised clustering | Alternate assignments and centroids; ++ spreads initial centers | Fast, interpretable compact-cluster baseline | Assumes Euclidean centroid geometry; sensitive to scale/outliers and chosen k | `n_clusters`, `n_init`, initialization; Mini-Batch variant reduces update cost |
| Agglomerative clustering; unsupervised clustering | Repeatedly merge clusters under linkage and distance rules | Hierarchy can reveal nested structure | Linkage choices change meaning; dense pairwise work can be costly | Number of clusters/distance threshold, linkage, metric; often best for smaller datasets |
| DBSCAN; unsupervised clustering/anomalies | Connect dense neighborhoods and label sparse points noise | Finds non-spherical clusters; does not require k | One density scale struggles with varying densities; high-dimensional distances are difficult | `eps`, `min_samples`, metric; neighborhood storage can become quadratic |
| Gaussian mixture/EM; unsupervised density/clustering | Alternate soft responsibilities and component parameter updates | Probabilistic overlapping groups and likelihood interpretation | Local optima, covariance singularities, component assumptions | `n_components`, covariance type, `reg_covar`, initialization; full covariance costs grow with dimension |
| PCA/SVD; unsupervised representation | Orthogonal directions capture variance / low-rank structure | Compression, denoising, correlated-feature summaries | Large variance need not be predictive; linear axes miss nonlinear structure | Components, scaling, solver; randomized or truncated solvers help larger arrays |
| t-SNE; unsupervised visualization | Match local neighborhood probabilities in a low-dimensional display | Useful exploratory local-neighborhood pictures | Global distances and cluster sizes are not faithfully interpretable; stochastic displays are not validation | Perplexity, learning rate, seed; computationally heavier than PCA |
| Isolation Forest; unsupervised anomaly detection | Random partitions tend to isolate unusual points in fewer splits | Scalable anomaly ranking baseline | Rare does not necessarily mean harmful; threshold choice needs operational evidence | Number of trees, subsample size, contamination convention |
| Local Outlier Factor; unsupervised anomaly detection | Compare local density to neighboring densities | Detects locally unusual points under varying density | Novelty mode and training-data scoring have different usage; scaling matters | Neighbors, metric, `novelty`; retain appropriate separate evaluation examples |
| One-Class SVM; unsupervised/novelty detection | Learn a boundary around normal training examples | Useful with well-defined normal data and suitable kernel | Sensitive to contamination, scale, and kernel; expensive at large n | `nu`, `gamma`, kernel; validate against realistic anomalies where possible |

## Choosing a method

First specify the prediction deadline, target, and error costs. Then choose a split respecting time and repeated entities. Compare a simple baseline, one linear method, and a suitable nonlinear method on the same protocol. Diagnose errors before expanding a search space. A tiny score difference may be less important than uncertainty, latency, calibration, or the cost of maintaining the system.

External boosting, advanced clustering/reduction, forecasting, Bayesian methods, neural architectures, language/vision algorithms, recommenders, and RL require their dedicated guide expansions. Their specifications remain visible in the syllabus; they are not silently omitted from the program.
